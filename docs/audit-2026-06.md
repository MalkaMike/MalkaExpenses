# Independent audit — June 2026

Ordered by Mickael 2026-06-10: independent audit of the whole app by two external
AI auditors (Gemini 2.5 Pro via vertex-ai MCP — auth-stack dossier; Codex via MCP —
API/data-integrity dossier, text-only because its Windows sandbox was broken),
plus an internal 3-agent exploration sweep. **Every external finding was
reproduced against the code before any fix** — peers advise, the repo decides.

Verdicts: ✅ EXECUTED (confirmed + fixed) · ❌ REJECTED (claim contradicted by code) ·
⚠️ FLAGGED (real, but destructive/architectural — needs Mickael sign-off) ·
📋 ACCEPTED RISK (real but deliberate; documented).

## Gemini findings (auth stack)

| # | Sev | Finding | Verdict |
|---|---|---|---|
| G1 | High | "household role check `!health && !secretary &&` breaks main-site access for the health user" | ❌ REJECTED — middleware line `if (health \|\| household) return next()` passes health users; the `!health &&` is short-circuit optimization, not a gate. Verified by reading the branch. |
| G2 | High | Rate limiter fails OPEN on DB outage → unthrottled brute force exactly when the store is down (login itself doesn't need the DB — bcrypt vs env hash) | ✅ EXECUTED — now fails CLOSED with a loud log. ## Codex findings (API / data integrity)

| # | Sev | Finding | Verdict |
|---|---|---|---|
| C1 | High | Household can PATCH a HIDDEN transaction by UUID (field-restricted, but the row "exists" and is editable) | ✅ EXECUTED — household + `shared_amount=0` → 404 (not 403, so existence isn't confirmed). |
| C2 | High | Privacy wall is code-only; service-role key bypasses Postgres — no RLS defense-in-depth | ⚠️ FLAGGED — correct observation; adding RLS/restricted DB roles is a schema + auth-model change with real lockout risk. Needs sign-off and a staged migration plan. |
| C3 | High | Outbox workers can double-send (no atomic row claim) | ✅ EXECUTED — atomic claim: `pending→sending` compare-and-set with a 10-min lease; crashed workers' rows become claimable after lease expiry. |
| C4 | High | Post-send DB write errors ignored → email out but row still pending → duplicate sends | ✅ EXECUTED — every `{ error }` checked; post-send persistence failure logs CRITICAL with the gmail message id. Residual risk noted: if the DB is down at that exact moment, manual reconciliation via logs. |
| C5 | High | `readFile(join(cwd, db_path))` trusts DB paths — `../` escapes attach arbitrary server files to outgoing email | ✅ EXECUTED — `safeLocalRead()` resolves and enforces paths stay under `<cwd>/private`. |
| C6 | Med | Lifecycle guard ran AFTER `sendEmail` → stale/cancelled claims could still be emailed | ✅ EXECUTED — claim state checked before send; non-sendable → terminal fail with reason, no retry. |
| C7 | Med | Attachment read failures swallowed → reimbursement email sent WITHOUT its documents | ✅ EXECUTED — missing required docs (NF always; prescription when linked) fail the row through the retry path; nothing incomplete is sent. |
| C8 | Med | "claim/docs not found" returned without incrementing attempts → infinite retry | ✅ EXECUTED — all failures route through one `failRow()` (attempts + backoff + terminal failed). |
| C9 | Med | `?force=1` GET is a side-effecting endpoint reachable by an admin's browser (CSRF-ish) | 📋 ACCEPTED RISK — requires a valid admin cookie; worst case triggers a queue run the cron does daily anyway; attacker controls no content. Not worth breaking the manual-trigger convenience. |
| C10 | Med | Money fields lack finite/domain validation (JS float ledger) | ✅ partially EXECUTED — `.finite()` on all money inputs (transactions, accounts). ⚠️ FLAGGED: integer-cents migration is an architectural change (DB + every consumer); needs sign-off. |
| C11 | Med | Household category edits silently train GLOBAL merchant rules (affecting rows she can't see) | ✅ EXECUTED — rule learning is now admin-only. |
| C12 | Med | Read→update→audit is non-transactional (stale audit rows under concurrency) | ⚠️ FLAGGED — needs Postgres RPC/transactions; meaningful churn, near-zero practical risk at 3 users. Needs sign-off. |
| C13 | Med | Pluggy webhook secret rides in the query string (leaks into logs) | ⚠️ FLAGGED — moving to signed-payload verification depends on what Pluggy supports per plan; needs investigation before touching a working integration. |
| C14 | Low | Account creation unaudited; `cc_issuer` not validated against type | ✅ EXECUTED (audit trail: `writeAudit("account.create")`). cc_issuer cross-validation skipped as over-engineering for one admin user. |
| C15 | Low | DELETE returns 404 for DB read failures (operational error disguised as not-found) | ✅ EXECUTED — `maybeSingle` + explicit 500 on error. |

## Datatable & UX standardization (owner directive)

- New shared **`components/data-table.tsx`** — typed, sortable (desc-first like merchants), responsive column hiding, expandable detail rows, plain Tailwind (no TanStack; largest dataset is a few hundred rows).
- **`/admin/historico`** → sortable table (Quando/Ação/Alvo/Antes→Depois/Tx/Impacto), row click expands the before/after detail.
- **`/transactions`** → desktop (`md+`) sortable table; **mobile keeps the date-grouped cards untouched** (Ayelet's flow). Same edit modal, same quick-hide.
- **`/admin/reembolsos`** → sortable table (status sorts by lifecycle order, not alphabet).
- **Kept as cards (documented decisions):** `/admin/inbox` is a bulk-select triage queue — checkbox cards beat a table for that job; `/admin/notas-encontradas` is a daily digest where day-grouping IS the feature.
- Admin dashboard "Operações rápidas" now links `/import` and `/admin/sugestoes`.

## Code quality

- `lib/http.ts safeJson()` — the single sanctioned body-parse catch; 53 scattered `.json().catch(() => ({}))` swallows replaced across 39 files.
- ESLint migrated off deprecated `next lint` → ESLint 9 flat config (FlatCompat); new lint ERROR bans `.catch(() => {})` — the rule immediately caught and fixed 2 real swallows (merchant-cluster warm-up, NF detail refresh; both now log).
- `eslint-config-next` aligned to the installed Next 15.5.
