# Casa — UX/UI Audit & Roadmap

**Date**: 2026-05-27
**Auditor**: ui-ux-specialist
**Benchmark apps**: Monarch Money, Mobills (BR), Organizze (BR), Lunch Money, YNAB, Mint, Empower/Personal Capital
**Scope**: full platform, all roles

---

## Methodology

For each surface we evaluate:
1. **Comprehension** — does a first-time user know what they're looking at in 3 seconds?
2. **Action clarity** — is the next-best-action obvious without thinking?
3. **Feedback** — does every user action have visible confirmation?
4. **Information density** — too sparse (feels empty) or too cluttered (feels chaotic)?
5. **Mobile-first** — does it work one-handed on a phone?
6. **Trust** — does it feel professional enough to handle real money?

## Critical issues (must fix this sprint)

### C1. No feedback during PDF upload
**Symptom**: button says "Enviando..." for 30–50s with no indication of progress or whether anything is happening. User clicks twice / refreshes / panics.
**Fix**: multi-stage progress UI: `Enviando arquivo → Analisando com IA → Pronto`. Show elapsed seconds. Animated state. Disable navigation away mid-upload.

### C2. No "done" confirmation after import
**Symptom**: import succeeds but the only signal is the preview disappearing. No "X movimentos importados, Y categorizados" with success animation. Users don't trust it.
**Fix**: success state with check icon, big number ("R$ 12.345 importados"), category summary preview, auto-redirect to dashboard after 3s with countdown.

### C3. Import + new-account gated to admin
**Symptom**: wife can't add a new bank account or import her own statements. Mickael becomes the bottleneck for normal household ops.
**Fix**: move `/admin/import` → `/import` and `/admin/accounts/new` → `/accounts/new`. Both accessible to household role. Real_amount editing + fake entries stay admin-only.

### C4. No PDF archive
**Symptom**: once a PDF is parsed, no way to retrieve the original file. If Gemini missed something, you have no source of truth.
**Fix**: `/admin/archive` page listing every `statement_imports` row with file metadata, download link to Supabase Storage, transaction count, parse status, re-process button.

## High-impact UX improvements (next 1–2 sprints)

### H1. Toast notification system
Every mutation needs a transient confirmation: "Conta criada", "Senha atualizada", "23 movimentos importados". Today nothing. Add `<Toaster>` + `toast.success/error()` API. Pattern: Sonner or hand-rolled. Auto-dismiss 4s. Pause on hover.

### H2. Transaction click → edit modal
A row is a static display today. Tapping should open: change category, rename description, edit shared amount (admin), hide from shared view (admin), add notes (admin), see audit history.

### H3. Bulk actions on transactions
Select multiple → set category, hide, mark as transfer, delete. Critical when a 227-tx PDF lands with imperfect AI categorization.

### H4. Date range filter
Today the transactions page shows the last 500. Need: This month / Last month / Last 3 months / This year / Custom range. Persists in URL `?from=2026-01-01&to=2026-01-31`.

### H5. Search across everything
A single global search box: "uber" → all uber transactions, "itau" → all from that account, "março 5000" → tx > R$5000 in March. Cmd+K / fab on mobile.

### H6. Quick-add manual transaction
Floating "+" button on transactions page → modal: date, amount, description, account, category. For cash transactions or things that never appear in statements.

### H7. Categories management
Today categories are seeded; can't add custom ones, rename, change icon/color. Add `/categories/manage` (admin) with reorder, rename, color picker, archive.

### H8. Improved empty states
Every page when there's no data should have:
- Friendly heading
- One-sentence explanation
- Big CTA button
- Optional illustration / icon
Current dashboard empty state is OK; transactions page is just "Nada por enquanto" — too cold.

### H9. Bank logos
Replace text labels "Itaú", "Bradesco" etc. with actual bank logos / branded color chips on account cards. ~30 minutes of asset work; massive trust upgrade.

### H10. Account icons by type
checking → bank icon, savings → piggy bank, credit_card → credit card icon. Today only credit_card has an inferred icon via category.

## Accessibility gaps (must address before broader use)

- [ ] Color contrast — verify all category colors meet WCAG AA on both light/dark
- [ ] Focus rings — currently relying on browser defaults; need explicit
- [ ] Screen reader labels — many icons lack aria-label
- [ ] Keyboard navigation — tab order through bottom nav + cards
- [ ] Form errors — currently only red text; need aria-describedby

---

## Performance opportunities

- [ ] Recharts pulls 130kB; bottom-nav routes that don't need charts shouldn't load it (route segmentation)
- [ ] Transaction list virtualizes nothing — at 1000+ tx, DOM bloats. Add virtual scrolling.
- [ ] Dashboard query fetches all 5000 tx every load; cache shared_transactions_v aggregates in a materialized view, refresh on import
- [ ] PDF parse blocks request thread for 35s+; move to async background job + polling
